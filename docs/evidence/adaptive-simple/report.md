# pgvector 与 PostgreSQL 关系查询的结合方式（基于自编示例资料）

状态：partial | 模式：live

引用经过来源校验；结论是否被原文支持仍需人工核对。

## 发现

- pgvector 是 PostgreSQL 的向量扩展；已有 PostgreSQL 的小型应用可以在关系数据库中保存向量，并把业务字段过滤与 SQL 查询组合起来使用，即在同一条关系查询中同时做标量条件过滤与向量数据访问。 [2]
- 对规模较小、关系数据关联较多的知识库，复用已有 PostgreSQL 可以减少额外的运维组件；查询性能仍取决于数据规模、索引、过滤条件与硬件，需在实际数据上验证。 [2]
- 关键词检索可以使用 PostgreSQL 全文检索，向量召回与关键词召回的结果需要独立融合；中文分词策略需要单独设计。 [2]
- 选型时应先确定资料量、向量维度、更新频率、权限过滤与检索质量要求再评估基础设施；已有 PostgreSQL、数据量小且关联查询多时，可以先验证 pgvector 的实际效果。 [1]
- 资料未给出向量相似度检索与关系字段过滤结合的具体 SQL 语法示例（如 ORDER BY 与 WHERE 的组合写法）或索引配置，也未给出百万向量的延迟、费用或吞吐量等量化数据，因此这些方面不作结论。 [2] [1]

## 资料缺口

- 缺少结合写法层面的实现细节：没有给出的具体 SQL 语法（如向量排序 ORDER BY 与业务字段 WHERE 过滤的组合写法）与索引配置示例。
- 缺少任何量化性能数据：资料明确不提供百万向量规模下的延迟、费用或吞吐量，故无法作出性能对比结论。
- 缺少与 Milvus 在同数据、同条件下的性能对比资料，无法判断两者延迟或吞吐量优劣。
