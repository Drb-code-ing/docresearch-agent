# 复杂真实任务受控样例

日期：2026-09-28。输入仅为仓库 `examples/corpus` 三份自编资料，代码基线为 `0323573`。用户充值并授权复测后执行，本次没有再出现 HTTP 402。

问题原文：

> 仅依据 examples/corpus 的自编资料比较 pgvector 与 Milvus 的小型知识库适用性。规划两个独立子任务分别研究两者，再安排第三个依赖前两个结果的子任务核对比较结论与原文的一致性。前两个研究者在私有 notes.md 写入笔记、读回并按版本修改标题；主代理只根据返回的结构化结果决定，最终引用子任务结论并保留部署成本或性能未知的缺口。

在已经完成 ingest、配置聊天/向量/重排接口与数据库的环境中，可使用以下同等参数复测；此命令会产生付费请求。凭据不包含在此目录。

```powershell
uv run docresearch run "仅依据 examples/corpus 的自编资料比较 pgvector 与 Milvus 的小型知识库适用性。规划两个独立子任务分别研究两者，再安排第三个依赖前两个结果的子任务核对比较结论与原文的一致性。前两个研究者在私有 notes.md 写入笔记、读回并按版本修改标题；主代理只根据返回的结构化结果决定，最终引用子任务结论并保留部署成本或性能未知的缺口。" --max-calls 80 --timeout 360
```

本题明确要求拆出三个任务，因此它验证真实模型执行指定协作结构，不是盲测模型能否自主判断任意问题的复杂程度。

建议按这个顺序看：

1. `run.json`：partial、error=null，3 个任务、并发峰值 2、62 次请求。显式上限 80，默认 48 是否足够未验证。
2. `tasks.json`：两个无依赖研究任务先做，verify_compare 依赖两者；三个任务均 completed。
3. `trace.json`：研究者完成 write_file/read_file/edit_file；核验在前两者结束后启动，终止结果曾被拒绝，修正后完成。
4. `report.md` 与 `sources.json`：逐条核对原文与结论。报告有重复表达；资料缺少价格与性能数值，不能强行填满。

值得注意的语义问题：milvus_study:f6 把笔记版本号引用到技术资料上，核验指出该资料不能证明版本号，最终主没有选入这条发现。原始输出保留该过程，不把来源 ID 有效当成答案必然正确。

这些是本机产物，不是提供方签名，也不是稳定性、准确率或平均延迟评测。未发布密钥、完整模型聊天或私有笔记正文。历史失败与预算边界见 [VALIDATION](../../VALIDATION.md)。
