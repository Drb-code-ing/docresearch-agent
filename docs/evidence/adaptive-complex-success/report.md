# pgvector 与 Milvus 的小型知识库适用性比较（仅依据 examples/corpus 自编资料）

## 发现

- pgvector 是 PostgreSQL 的向量扩展；已有 PostgreSQL 的小型应用可在关系数据库中保存向量，并把业务字段过滤与 SQL 查询组合使用，关键词检索可用 PostgreSQL 全文检索。 [3]
- 适用场景：规模较小、关系数据关联较多的知识库；已有 PostgreSQL、数据量小且关联查询多时，可先验证 pgvector 实际效果。 [3] [1]
- 限制/注意事项：查询性能取决于数据规模、索引、过滤条件与硬件，需在实际数据上验证；向量召回与关键词召回结果需独立融合；中文分词策略需单独设计。 [3]
- 部署与运维特征：复用 PostgreSQL 可减少额外运维组件；相较之下引入独立向量库（Milvus）可分别规划检索容量与业务数据库，但增加部署组件、监控、备份和数据同步的维护工作。 [3] [2]
- 资料性质：pgvector.md 与 milvus.md 均自述为项目自编的演示资料，非性能测试报告或完整产品文档，因此不能据此得出量化或对比性结论。 [3] [2]
- 增长路径：向量规模增长并需要独立扩展检索容量时，再评估 Milvus 的维护成本与检索表现；任何性能、召回率与费用结论必须来自相同数据与条件下的测试。 [1] [2]
- Milvus 定位为面向向量检索的数据库，能力上支持多种向量索引和标量过滤。 [2]
- 选型需考虑向量规模、更新频率、查询模式；检查表要求先确定资料量、向量维度、更新频率、权限过滤和检索质量，再评估基础设施。 [2] [1]
- 部署/运维特征：采用独立向量数据库可使检索容量与业务数据库分别规划，但会增加部署组件、监控、备份和数据同步等维护工作。 [2]
- 适用场景：小型知识库是否用 Milvus 取决于已有基础设施与预期增长，不能仅因功能多就断言优于 PostgreSQL 向量扩展；当向量规模增长并需独立扩展检索容量时可评估 Milvus。 [2] [1]
- 资料性质：两份材料均为项目自编演示资料，明确声明非性能测试报告/完整产品文档，且要求结论须来自同数据同条件测试（pgvector.md 有相同免责声明）。 [2] [1] [3]
- pgv_study:f1~f4 全部支持。pgvector.md 原文（e5a95ea4d55ef429）直述：pgvector 是 PostgreSQL 向量扩展；小型应用可保存向量并组合业务字段过滤与 SQL；小型且关联多的知识库复用 PostgreSQL 可减少额外运维组件；性能取决于数据规模/索引/过滤条件/硬件需实测；全文检索可用于关键词、两路召回需独立融合、中文分词需单独设计。milvus.md（4be8254c3582f23b）亦印证独立向量库会增加部署组件、监控、备份、数据同步维护。 [3] [2]
- pgv_study:f2/f6 与 milvus_study:f2/f4 支持。selection.txt（1274227b93ceec10）原文：先定资料量、向量维度、更新频率、权限过滤与检索质量，再评估基础设施；“已有 PostgreSQL、数据量小且关联查询多时，可以先验证 pgvector 的实际效果”；“向量规模增长并需要独立扩展检索容量时，可以评估 Milvus 的维护成本和检索表现”。无过度推断，也未把 Milvus 判为必然更优。 [1] [2]

- 修正后的比较结论（限原文支持）：小型知识库在“已有 PostgreSQL + 数据量小 + 关联查询多”时可先验证 pgvector，其优势是可减少额外运维组件；Milvus 适合需将检索容量与业务库分别规划的情形，代价是部署组件、监控、备份、数据同步维护增加。是否选用取决于已有基础设施与预期增长，不能仅因组件功能多就断言优于 pgvector；两者延迟/吞吐/召回优劣原文不作判定。 [3] [2] [1]
